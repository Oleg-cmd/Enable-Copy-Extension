# Build Instructions for Enable Copy Extension Source Code

This document provides instructions for reviewers to build the Enable Copy Extension from the provided source code archive and verify it matches the submitted extension package.

## Build Environment Requirements

*   **Operating System:** The build should be runnable on standard Linux distributions (like Ubuntu 24.04), macOS, or Windows (with appropriate shell environment like Git Bash or WSL). The default AMO reviewer environment (Ubuntu 24.04 LTS) is expected to work.
*   **Node.js:** Node.js LTS version 22.x is recommended (matches the default reviewer environment). Check `.nvmrc` if present, otherwise use the latest LTS.
*   **npm:** npm version 10.x (comes with Node 22) or compatible.

## Build Steps

1.  **Extract Archive:** Unzip the source code archive (`<extension-name>-v<version>-src.zip`) into a new directory.
2.  **Navigate to Directory:** Open a terminal or command prompt and change into the extracted directory:
    ```bash
    cd <directory-name-where-you-extracted>
    ```
3.  **Install Dependencies:** Install the exact dependencies listed in `package-lock.json`. **It is crucial to use `npm ci` instead of `npm install`** to ensure the exact dependency tree is replicated.
    ```bash
    npm ci
    ```
4.  **Run Production Build:** Execute the build script defined in `package.json`. This typically bundles the code using Webpack and creates the final extension files.
    ```bash
    npm run build
    ```
5.  **Locate Build Output:** The build process will generate the final, bundled extension files in the `dist/` directory within the project folder. The command might also create a final ZIP archive (e.g., `enable-copy-extension-vX.Y.Z.zip`) in the `releases/` directory (this generated ZIP is *not* the source code archive).

## Verification

*   Compare the contents of the newly generated `dist/` directory with the files inside the `.zip` package originally submitted to AMO for review.
*   The files and their contents (excluding potentially generated source maps if they weren't included in the original submission) should be identical.
*   Alternatively, compare the contents of the ZIP file generated by `npm run build` (if any, in the `releases/` folder) with the originally submitted extension package.

Thank you for reviewing!
